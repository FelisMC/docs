# 平台管理 {#administration}

本页说明所有者与管理员如何管理 Felis 平台：角色与用户、配额、镜像白名单、构建流水线与投稿审核、平台设置以及审计日志。主机层面的运维操作见[运维概览](/operations/#panel-host-operations)。

## 角色 {#roles}

Felis 有三种角色：

| 角色 | 权限 | 面板导航 |
| --- | --- | --- |
| 所有者 | 平台所有者，具备管理员的全部权限，并管理用户、认证源、主机运维与平台设置。还可执行服务器的应急停止与转发方式设置。 | 「平台」：用户管理、认证源、维护与备份、平台设置 |
| 管理员 | 创建服务器、编辑服务器配置并管理全部服务器，维护登录空间与大厅、镜像白名单、构建与投稿审核；多机部署中选择执行节点并迁移服务器。 | 「管理」：登录与大厅、镜像、构建流水线、审核提交 |
| 普通用户 | 认领服务器，管理自己拥有的服务器，提交模组包。 | 仪表盘、服务器、我的提交、账户 |

所有角色都可以使用仪表盘、服务器、我的提交与账户。所有者账户由[设置向导](/guide/deployment#setup-wizard)创建，其角色在面板中不能修改，账户也不能被禁用或删除；所有者无法登录时，在主机上使用 `sudo felis breakGlass` 恢复，见[应急访问](/operations/access#break-glass)。

### 登录方式 {#sign-in}

| 控制台 | 地址 | 使用者 | 登录方式 |
| --- | --- | --- | --- |
| 玩家控制台 | `https://console.<根域名>` | 普通用户 | 游戏绑定码、邮箱验证码、通行密钥 |
| 运维控制台 | `https://op.console.<根域名>` | 所有者、管理员 | 通行密钥、邮箱验证码、管理员登录请求 |

管理员登录请求的流程：在运维控制台选择「管理员登录」，填写邮箱后选择「发起管理员登录」；验证码发送到邮箱，同时须由一位在线且已关联游戏身份的管理员或所有者在游戏中执行 `/felis web op approve <代码>` 批准，批准后输入邮件中的验证码完成登录。

运维账户的会话连续 30 分钟无操作后自动退出。敏感操作（如保存平台设置、执行主机任务、下载诊断包）要求重新验证身份：使用已注册的通行密钥或已验证邮箱完成验证，验证结果 5 分钟内有效；运维账户重新登录后的 5 分钟内同样视为已验证。邮件服务未配置时无法发送验证码，见[邮件服务](#mail-relay)。

## 用户管理 {#users}

所有者在「平台 → 用户管理」中管理平台账户。列表支持按用户名或邮箱搜索，并按角色与状态筛选。

### 创建用户 {#create-user}

1. 选择「创建用户」，填写用户名。
2. 在新用户的详情页「已关联的 Minecraft 账号」中选择「关联账号」，选择「验证源」（Mojang 或第三方 Yggdrasil）并填写其游戏身份。
3. 用户在游戏中执行 `/link` 获取绑定码，在玩家控制台登录；绑定邮箱或注册通行密钥后，也可以使用邮箱验证码或通行密钥登录。

账户没有密码。玩家也可以直接用游戏中获得的绑定码创建自己的账户，见[关联账户](/guide/players#account-linking)。

### 用户详情 {#user-details}

在用户列表中选择「详情」，可以执行以下操作：

- **编辑资料**：修改用户名、邮箱与角色（管理员或普通用户），选择「保存更改」。
- **已关联的 Minecraft 账号**：关联或「解除关联」游戏身份。解除关联后，用户失去该 UUID 绑定的游戏内身份。
- **配额**：见[配额](#quotas)。
- **活跃会话**：撤销单个会话，或选择「全部撤销」使用户从所有设备登出。
- **危险操作区**：
  - 「禁用用户」阻止用户登录并立即撤销其全部会话；「启用用户」恢复登录。
  - 「解绑通行密钥」移除该账户的全部通行密钥，用于处理密钥丢失或泄露；邮箱验证码与游戏内审批等其他登录方式不受影响。
  - 「删除用户」软删除账户：其拥有的服务器被释放，全部会话被撤销，账户永久禁用。此操作无法在面板中撤销。

当前登录的账户不能修改自己的角色，也不能禁用或删除自己。

## 配额 {#quotas}

所有者在用户详情的「配额」中限制账户可拥有的资源：

| 字段 | 说明 |
| --- | --- |
| 最大服务器数 | 账户可拥有的服务器数量。 |
| 最大 CPU（毫核） | 账户全部服务器的 CPU 限制总和。 |
| 最大内存（MiB） | 账户全部服务器的内存总和。 |
| 最大存储（GiB） | 账户全部服务器的世界卷容量总和。 |

字段留空表示不限制，填 `0` 表示不分配该项资源。未设置配额的账户不受限制。

配额在认领服务器、管理员增加已归属服务器的 CPU 或内存、以及通过账户迁移接收服务器时检查，超出配额的操作被拒绝。降低配额只限制后续操作，不影响已有服务器；管理员可通过减小服务器规格使账户回到配额之内。已放弃但尚未处理的服务器仍计入配额。配额对用户的影响见[配额](/guide/servers#quotas)。

平台范围的同时运行服务器上限在平台设置中设置，见[启动与唤醒策略](#wake-policy)。模组包投稿另有限制：每个用户最多 5 个待审核提交；默认单个构建上下文最大 1 GiB，每个用户的上传总量 2 GiB，全部用户合计 4 GiB，分别由 `felis.toml` 中 `[registry]` 的 `context_max_bytes` 与 `user_uploads_max_bytes` 等键调整。

## 镜像白名单 {#images}

服务器只能使用镜像白名单中已启用的镜像。管理员在「管理 → 镜像」中维护白名单，列表显示每个镜像的来源：

| 来源 | 说明 |
| --- | --- |
| 平台构建 | 构建流水线成功构建的镜像，构建完成后自动加入白名单。 |
| 外部 | 管理员手动登记的镜像引用。 |
| 推荐 | 由 Felis 提供的镜像，创建服务器时优先显示，准入规则与其他镜像相同。 |

添加外部镜像：

1. 选择「添加镜像」。
2. 在「镜像引用」中填写镜像，例如 `registry.felis.svc:5000/image:tag`。
3. 确认添加。

白名单条目可以是具体标签、`:*` 通配符或镜像摘要。选择「移除镜像」后，新服务器不能再选用该镜像。服务器的镜像兼容要求见[镜像与 Minecraft 版本](/guide/servers#images-versions)。

## 构建流水线 {#build-pipeline}

「管理 → 构建流水线」列出镜像构建任务的历史，并可手动触发构建。构建在隔离的 `felis-build` 命名空间中由 Kaniko 执行，完成后由 Trivy 进行安全扫描；扫描通过的镜像推送到集群内镜像仓库并加入白名单。

手动触发构建：

1. 在「触发新镜像构建」中填写「镜像引用」（目标镜像）、「构建上下文引用」与「基础镜像」，或在「从已有的审核提交导入参数」中选择一个提交自动填写。
2. 「Dockerfile 内容」仅作审计记录保存；实际执行的是构建上下文压缩包中的 `Dockerfile`。
3. 选择「开始构建」。

手动构建不会把对应的提交标记为已通过，也不会更新其构建状态，仅用于应急调试。

同时运行的构建数量由 `[registry] max_concurrent_builds` 限制，默认 2，取值 1–6；超出时任务排队，前一个构建结束后自动开始。选择「扫描与日志」查看构建日志与「安全扫描」结果，可下载「Trivy 报告」与「SBOM」。扫描默认在发现已有修复版本的 CRITICAL 级别漏洞时阻止镜像，没有修复版本的漏洞仅列出。阻止的级别由 `[registry] scan_fail_on` 设置；开启 `scan_fail_unfixed` 后，没有修复版本的漏洞也会阻止镜像；`scan_accept` 中列出的已知风险不会阻止镜像。被阻止的镜像不会推送到镜像仓库。运行中的构建可选择「取消」停止，停止后不推送任何内容。

构建失败的排查见[构建失败](/operations/troubleshooting#build-failures)与[构建 Pod 无法启动](/operations/troubleshooting#build-pods-not-starting)。

## 审核提交 {#submissions}

用户可以提交自定义模组包，经管理员审核通过后自动构建，构建成功的镜像加入白名单并可用于创建服务器。

### 提交模组包 {#submit-modpack}

1. 打开「我的提交」，在「提交新模组包」中填写「显示名称」。
2. 选择「构建上下文 (.tar.gz)」文件，即包含 `Dockerfile` 的 gzip 压缩包，大小上限显示在上传区域。
3. 选择「提交」。上传按 32 MiB 分片进行，可「暂停」并「继续上传」，中断后从已确认的位置续传。

提交列表显示审核状态（等待审核、审核通过、已拒绝）、构建状态与「上下文 SHA-256」，可用 `sha256sum` 与本地文件核对。待审核的提交可以「撤回提交」，撤回会删除提交与已上传的构建上下文，并释放对应的待审核名额与存储配额。

### 审核 {#review}

1. 管理员打开「管理 → 审核提交」，选择待审核的提交。
2. 选择「下载上下文」下载构建上下文，其中的 `Dockerfile` 即实际执行的内容。离线审查时使用 `sha256sum` 核对页面显示的「上下文 SHA-256」。
3. 审查通过后选择「通过」。通过会固定当前上下文的摘要，并自动启动 Kaniko 构建与 Trivy 安全扫描。
4. 需要拒绝时选择「驳回」，在「驳回原因」中填写原因（最多 1000 字符），原因会展示给提交者。

提交者在审核后重新上传了上下文时，通过操作被拒绝，须下载并审查最新版本。尚未上传上下文的提交无法通过。不再需要的提交可选择「删除提交」。

## 平台设置 {#platform-settings}

所有者在「平台 → 平台设置」中管理平台范围的设置，各项分布在四个标签页中：

| 标签页 | 卡片 |
| --- | --- |
| 玩家进入 | 玩家进入策略（见[玩家进入策略](/guide/players#entry-policy)）、启动与唤醒策略 |
| 通知与保留 | 邮件服务、监控心跳、备份与审计保留 |
| 访问与安全 | 访问方式与域名、上传存储、凭据轮换、游戏代理、系统服务器补全 |
| 分布式 | 多节点分布式部署、节点操作、执行节点、故障切换（见[多机部署与高可用](/guide/distributed#overview)） |

保存设置须完成身份验证，并基于当前版本保存；他人在此期间修改了同一设置时，保存被拒绝，须重新读取后再编辑。面板中保存的设置优先于安装时的设置，优先级说明见[面板设置的优先级](/reference/configuration#panel-settings-precedence)。

### 启动与唤醒策略 {#wake-policy}

| 设置 | 说明 |
| --- | --- |
| 同时运行的服务器上限（0–10000） | `0` 表示不限制。启动时计入已运行与已请求运行的服务器；系统服务始终可以启动。上限统一用于面板启动、游戏内唤醒与计划任务，降低上限不会停止现有服务器。 |
| 唤醒冷却时间（0–3600 秒） | 同一服务器两次被接受的唤醒请求之间的最短间隔，`0` 表示关闭冷却。 |

运行上限用于启动准入，并发请求可能短暂超出上限；服务器能否实际调度仍取决于节点的可用内存。选择「保存并生效」后，设置立即在所有 API 实例上生效，无需重启。

### 邮件服务 {#mail-relay}

邮件服务用于发送登录验证码、身份确认邮件与告警邮件。在「通知与保留 → 邮件服务」中填写：

| 字段 | 说明 |
| --- | --- |
| 服务器地址、端口 | 邮件服务商的 SMTP 中继。端口可选 587（STARTTLS，推荐）、465（SSL/TLS）、25 或 2525。 |
| 发件地址 | 须为邮件服务商已授权的发件身份，否则投递时被拒收。 |
| 用户名、密码 | 中继的认证信息。已保存的密码留空表示不修改。 |
| 每小时发信上限 | `0` 使用默认上限，每小时 120 封。应不高于邮件服务商的限额。 |
| 要求加密连接 | 开启后，服务器不支持 STARTTLS 时拒绝发信。仅在通过可信内网连接邮件服务器时关闭。 |

选择「检查并保存」时，系统先向发件地址发送一封自检邮件，投递成功后才保存。「发送测试邮件」可随时验证配置。保存的设置覆盖安装时通过 `felis setup` 写入的设置，立即对 API、看门狗、闲置清理与应急登录生效，无需重启。选择「恢复为安装时的设置」可改回安装配置；安装时未配置邮件服务时，将无法发送邮件验证码。邮件问题的排查见[邮件中继](/operations/monitoring#mail-relay)。

### 监控心跳 {#heartbeat}

在「通知与保留 → 监控心跳」中填写外部监控服务（如 Healthchecks.io）提供的心跳地址。看门狗每两分钟运行一次，每次运行都访问该地址；访问停止时，例如主机宕机或看门狗本身失败，监控服务发出通知。

地址须以 `http://` 或 `https://` 开头。地址中的路径即检查的密钥，保存后只显示协议与主机名。面板中的地址优先于安装时写入主机的地址。选择「移除心跳地址」后，看门狗不再访问该地址，监控服务会因心跳停止而告警，请同时在监控服务中停用该检查。详见[外部心跳](/operations/monitoring#heartbeat)。

### 备份与审计保留 {#retention}

「通知与保留 → 备份与审计保留」中的设置优先于 `felis.toml` 中的 `[archive]` 与 `[audit]`：

| 分组 | 字段 | 取值范围 | 安装默认值 |
| --- | --- | --- | --- |
| 手动备份 | 每台服务器保留份数 | 1–100，超出后删除最旧的一份 | 5 |
| 手动备份 | 保留天数 | 1–3650 天 | 30 天 |
| 手动备份 | 两次备份的最短间隔（分钟） | 0–1440，`0` 表示不限制；管理员不受限制 | 10 分钟 |
| 定时还原点 | 间隔（小时） | 0–720，`0` 表示关闭；只为上次还原点之后有人游玩过的世界创建 | 24 小时 |
| 定时还原点 | 每台服务器保留份数 | 1–100 | 7 |
| 定时还原点 | 保留天数 | 1–3650 天 | 90 天 |
| 存储与审计 | 已移除世界的归档保留天数 | 1–3650 天。世界因闲置被回收、被释放或被删除前先归档，该归档保留此天数 | 90 天 |
| 存储与审计 | 备份存储上限（GiB） | `0` 表示不限制。达到上限后暂停手动备份与定时还原点 | 不限制 |
| 存储与审计 | 审计记录保留天数 | `0` 表示永久保留，其余为 30–3650 天 | 365 天 |

选择「保存保留设置」后，felis-api 立即使用新设置，备份任务与回收任务在下一次运行时使用。「恢复为安装时设置」丢弃面板中的数值，改回 `felis.toml` 的设置。备份的完整说明见[世界备份](/operations/backup#world-backups)。

### 访问与安全 {#access-security}

「访问与安全」标签页中的操作由主机上的节点操作服务以 root 身份执行，同一时刻只运行一项任务，每项操作都须完成身份验证并记入审计日志：

| 卡片 | 作用 | 说明 |
| --- | --- | --- |
| 访问方式与域名 | 切换直接访问、自有反向代理或 Cloudflare Tunnel，检查与更换根域名 | [访问方式](/operations/access#access-methods)、[更换根域名](/operations/access#change-domain) |
| 上传存储 | 切换投稿上传内容的存储位置 | [上传存储](/operations/storage#upload-storage) |
| 凭据轮换 | 替换系统生成的凭据并重启使用它的组件 | [凭据轮换](/operations/access#rotate-credentials) |
| 游戏代理 | 设置 Velocity 的内存上限，取值 256M 至 64G，默认 1G 适合约 100 名同时在线玩家；应用后代理重启，所有玩家断开 | [资源规划](/guide/requirements#sizing) |
| 系统服务器补全 | 为早期创建的服务器补全新版本引入的设置，可选为旧用户服务器启用 RCON | [felis converge](/reference/cli#converge) |

主机任务的执行规则与完整操作清单见[在面板中运维主机](/operations/#panel-host-operations)。

## 审计日志 {#audit-log}

Felis 将管理操作与敏感操作记入审计日志，每条记录包含时间、操作者、操作类型、服务器与操作参数。记录的操作包括：

- 服务器：创建（`server.create`）、备份（`backup.create`、`backup.scheduled`）、删除备份（`backup.delete`）、下载备份与导出世界（`backup.export`、`world.export`）。
- 文件：`file.write`、`file.mkdir`、`file.delete`、`file.rename`、`file.upload`、`file.unzip`、`file.download`。
- 计划任务：`schedule.create`、`schedule.update`、`schedule.delete`、`schedule.run_now`，以及每次执行完成后的 `schedule.run`。
- 平台：平台设置的修改（`platform.*`，如 `platform.entry_policy`、`platform.archive_policy`）、主机任务（`platform.host.*`）与节点操作（`platform.node.*`）。
- 登录：每次被拒绝的登录记为 `auth.<入口>.failed`，载荷中的 `reason` 说明原因；被限流的请求记为 `auth.rate_limited`。这些记录包含账户 ID、客户端地址与 User-Agent。

审计记录默认保留 365 天，保留天数在[备份与审计保留](#retention)中设置。felis-api 在启动后一分钟及此后每 6 小时清理过期记录；每日数据库备份中的记录随备份保留。需要长期保存时，在保留期结束前导出：

1. 打开「维护与备份 → 备份」，找到「导出审计日志」卡片。
2. 选择「起始日期（含）」与「截止日期（不含）」，留空表示从最早或至最新的记录。
3. 选择「下载」，并完成身份验证。记录以 JSON Lines 格式下载。

在主机上也可以使用命令行导出：

```bash
sudo felis db audit-export -since 2026-01-01 -until 2026-07-01 -out /root/felis-audit-2026h1.jsonl
```

`-since` 与 `-until` 接受日期（UTC 零点）或 RFC 3339 时间，导出区间包含起点、不含终点，每行一条记录，按时间从旧到新排列。`-out` 指定的文件以 0600 权限创建，已存在的文件不会被覆盖；省略 `-out` 时输出到标准输出。查看最近的审计记录：

```bash
sudo k3s kubectl -n felis exec deploy/felis-postgres -c postgres -- psql -U postgres felis -c \
  "SELECT created_at, actor, action, server_name, payload FROM audit_logs ORDER BY created_at DESC LIMIT 20;"
```
