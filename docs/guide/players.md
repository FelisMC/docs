# 玩家接入 {#players}

本页说明玩家如何通过游戏代理进入服务器并关联面板账户，以及所有者与管理员如何配置认证源、玩家进入策略、登录空间与正式大厅。前两节面向玩家，其余各节面向所有者与管理员。

## 进入服务器 {#joining}

玩家使用 Minecraft Java 版连接，所需的客户端版本显示在面板「账户」页的「准备进入 Minecraft」中。登录空间与正式大厅使用这一版本；目标服务器可能需要其他版本或模组，以服务器所有者的说明为准。

每台服务器的地址为 `<子域名>.<根域名>`，可在面板「服务器」列表中复制。游戏代理监听非默认端口时，地址附带端口号。

在默认的玩家进入策略下，进入过程如下：

1. 游戏代理（Velocity）验证玩家的游戏身份：先向 Mojang 验证，再按顺序查询已启用的第三方认证源，见[认证源](#auth-sources)。
2. 玩家进入登录空间。尚未关联面板账户的玩家在这里获得绑定码并完成网页登录，见[关联账户](#account-linking)；已关联的玩家直接通过。
3. 目标服务器正在运行时，玩家被直接传送过去。目标服务器处于休眠状态时，系统按其[自动启动策略](/guide/servers#autostart)唤醒服务器，玩家在正式大厅中等待，启动期间每分钟收到一次进度提示，服务器就绪后被自动传送。

所有者可以修改进入方式，例如直接进入主服务器或跳过账户关联，见[玩家进入策略](#entry-policy)。

在服务器列表中，各服务器的 MOTD 显示其当前状态（在线、启动中或休眠）；刷新服务器列表不会唤醒服务器。

### 大厅菜单 {#lobby-menu}

在正式大厅中执行 `/menu` 打开服务器菜单。菜单按玩家的客户端语言显示，为每台服务器显示一个磁贴，玩家自己的服务器排在前面，标有 ★ 与「你的服务器」：

| 磁贴 | 含义 |
| --- | --- |
| 加入（绿色） | 服务器已运行，点击后进入。 |
| 认领并启动（金色） | 服务器无所有者，点击后认领并启动。 |
| 启动（红色） | 服务器处于休眠状态，点击后唤醒，就绪后自动进入。 |
| 无法启动（灰色） | 当前玩家无权启动，原因显示在说明与聊天栏中。 |

### 游戏内命令 {#commands}

| 命令 | 作用 |
| --- | --- |
| `/link` | 获取一次性绑定码，用于关联面板账户。 |
| `/menu` | 在正式大厅中打开服务器菜单。 |
| `/felis` | 显示代理与路由状态，`/felis help` 列出全部命令。 |
| `/felis server` | 列出代理已知的服务器。 |
| `/felis go <服务器>` | 启动服务器，并在就绪后将玩家传送过去。 |
| `/felis lobby` | 回到正式大厅。 |
| `/felis claim` | 认领当前所在的服务器。 |
| `/felis migrate` | 发起账户迁移，将本账户的服务器转移到另一个账户。 |
| `/felis web` | 显示网页控制台地址。 |
| `/felis web op approve <代码>` | 查看并批准待处理的管理员登录请求，仅限管理员与所有者。 |
| `/invite <玩家>` | 邀请一名在线玩家来到当前服务器；被邀请者使用 `/invite accept` 接受或 `/invite deny` 拒绝。 |

`/felis` 系列命令在登录空间中不可用，须先完成登录。

### 无法进入时的提示 {#join-refusals}

| 提示 | 原因 |
| --- | --- |
| 无权启动该服务器 | 服务器的自动启动策略不允许该玩家唤醒。 |
| 服务器正在维护 | 备份、恢复或文件修改正在进行，完成后重试。 |
| 服务器闲置过久，世界正在归档 | 世界回收正在归档该世界。 |
| 稍后再试 | 平台已达到同时运行的服务器上限。 |
| 登录超时，请重连 | 未在登录等待时间内完成网页登录。 |
| 此游戏身份已被禁止登录 | 该游戏身份在全局黑名单中，见[全局黑名单](#blacklist)。 |

其他进入问题见[玩家无法进入](/operations/troubleshooting#players-cannot-join)。

## 关联账户 {#account-linking}

关联账户将面板账户与经过验证的游戏身份绑定。关联后才能认领、启动、停止与管理服务器。绑定码由 8 位字符组成，约 10 分钟内有效，只能使用一次。

### 首次登录玩家控制台 {#first-sign-in}

玩家无需事先注册，使用游戏中获得的绑定码即可创建账户并登录：

1. 使用 Minecraft Java 版连接服务器。登录空间显示一本登录书，并在聊天栏给出绑定码与玩家控制台链接。
2. 在系统浏览器中打开链接 `https://console.<根域名>`。请勿使用微信或 QQ 的内置浏览器，通行密钥在其中无法使用。
3. 选择「使用游戏绑定码登录」，输入绑定码，选择「验证并登录」。系统创建账户、关联游戏身份并登录。
4. 返回游戏，登录空间确认关联后将玩家送往正式大厅。

登录空间默认等待 600 秒，超时后断开连接，重新连接即可获得新的绑定码。之后可随时在游戏中执行 `/link` 获取新绑定码登录。在「账户」页验证邮箱或注册通行密钥后，也可以使用邮箱验证码或通行密钥登录。

### 为已有账户关联游戏身份 {#link-existing}

1. 在游戏中执行 `/link`，获得绑定码。
2. 在面板打开「账户」，在「Minecraft 关联」中输入绑定码，选择「关联」。

同一个游戏身份只能关联一个面板账户。关联错误的说明见[账户关联与认领错误](/operations/troubleshooting#account-link-errors)。

所有者与管理员还可以按角色查询关联：在「账户」页选择「认证源」，输入「Minecraft 角色名或 UUID」，选择「查询角色」，再选择「确认关联此角色」。认证源未配置角色查询 API 时，改用游戏内绑定码。管理员与所有者的游戏身份不能用于在玩家控制台登录，须在运维控制台登录，见[角色](/guide/administration#roles)。

### 账户设置 {#account-settings}

「账户」页还提供以下功能：

- **邮箱验证**：输入邮箱获取 6 位验证码，验证码 10 分钟内有效。
- **Passkey 注册管理**：注册或删除通行密钥。账户只剩一个通行密钥且邮箱未验证时，不能删除该密钥。
- **已登录的设备**：查看浏览器会话，撤销未知设备的会话，或选择「退出其它设备」。
- **API 密钥**：供脚本以本人身份调用外部接口，仅在平台所有者开启该功能后可创建。在「账户 → API 密钥」选择「创建密钥」，填写名称并选择有效期（30 天、90 天、1 年或不过期，默认 90 天）。密钥的明文只在创建后显示一次，关闭对话框后无法再次查看，须先复制保存。每个账户最多 10 个密钥，达到上限后须先撤销不再使用的密钥。在列表中选择「撤销」后，使用该密钥的脚本立即失效。请求格式见 [API 密钥](/reference/api#api-keys)。

### 面板外观 {#panel-appearance}

在侧栏底部选择「主题」，可设置「浅色」「深色」或「跟随系统」。默认跟随系统，选择保存在当前浏览器中，刷新或重新打开面板后继续生效。选择固定的浅色或深色后，系统外观变化不会改变面板主题。移动端的主题入口位于顶部栏。

### 账户迁移 {#account-migration}

账户迁移将一个退役账户名下的全部服务器转移到另一个账户：

1. 使用要退役的账户在游戏中执行 `/felis migrate`。
2. 在面板中登录该退役账户，打开「账户 → 账户迁移」，选择「使用 Passkey 确认」或「发送验证码到我的邮箱」完成身份核验。
3. 填写目标账户「账户」页显示的「账户 ID」，选择「签发转移码」。转移码只显示一次，签发后会向已验证的邮箱发送通知。
4. 登录目标账户，在「账户迁移」中输入转移码，选择「使用转移码」。

迁移完成后退役账户停用。目标账户的配额不足时，使用转移码被拒绝，转移码保持有效，提高配额后可再次使用。迁移的服务器上的计划任务自动停用，须由新所有者确认后重新保存。

## 认证源 {#auth-sources}

认证源决定游戏代理接受哪些游戏身份。Mojang 正版验证内置且始终启用，排在首位；所有者可在「平台 → 认证源」中添加第三方 Yggdrasil 认证站，验证顺序为 Mojang 之后按列表自上而下。

### 添加认证源 {#add-auth-source}

1. 打开「平台 → 认证源」，选择「添加认证源」。
2. 填写以下字段：

   | 字段 | 说明 |
   | --- | --- |
   | 永久标识 | 唯一标识，不能包含冒号或首尾空格。保存后固定，用于保留玩家 UUID 与账户关联。 |
   | 重名处理前缀 | 1–4 位字母或数字，忽略大小写后须唯一。该认证源的玩家与正版玩家重名时，游戏内名称变为 `<前缀>_<名称>`。 |
   | 认证接口（hasJoined） | 完整的 `hasJoined` 地址。须使用 HTTPS，仅本机地址或私有 IP 允许 HTTP；不能包含查询参数或片段。 |
   | 角色查询 API 根地址（选填） | 标准 `hasJoined` 地址可留空；使用自定义认证路径时，填写 Yggdrasil API 根地址，以便按角色名或 UUID 查询。 |

3. 选择「测试连接」检查认证接口。接口对未登录的会话返回 HTTP 204 即为通过；此检查不保存配置，也不检查启动器配置与角色查询 API。
4. 使用「上移认证源」「下移认证源」调整顺序。
5. 选择「保存并生效」，并完成身份验证。

保存后的配置用于下一次登录与角色查询，无需重启，在线玩家不会断开。面板中保存的配置优先于安装配置中的 `[[auth_source]]` 列表；首次打开页面时，页面导入安装配置中的列表。Felis-nano 继续使用其 TOML 配置。

### 身份、停用与删除 {#auth-identities}

- 正版玩家保留 Mojang UUID。第三方认证源的玩家使用以永久标识划分的独立 UUID 空间，不同认证源的身份不会冲突。
- 取消「启用」并保存后，不再接受该认证源的登录；永久标识保留，重新启用即可恢复相同的玩家身份。
- 选择已保存认证源上的删除图标并确认后，该认证源即被删除，选择「保存并生效」后生效。该认证源的玩家无法再登录，其账户关联、服务器数据与封禁记录保留。永久标识继续保留给该认证源原有的认证接口：以相同标识和相同认证接口重新添加即可恢复这些玩家的身份，该标识不能用于其他认证接口。
- 修改认证接口地址会改变由谁验证该标识下的身份，请始终指向同一个可信服务。
- 玩家的启动器须配置同一个认证站。
- 读取数据库失败时，系统拒绝新的认证，不会回退到旧的或已停用的认证源。
- 另一位所有者在此期间修改了配置时，保存被拒绝并保留草稿；选择「放弃更改」并「重新读取」后再编辑。

## 玩家进入策略 {#entry-policy}

玩家进入策略决定代理在验证身份后将玩家送往何处，独立于游戏身份认证与面板账户关联。所有者在「平台设置 → 玩家进入 → 玩家进入策略」中配置。

| 进入方式 | 认证后的目标 |
| --- | --- |
| 正式大厅 | 进入正式大厅，由玩家选择服务器。 |
| 直达主服 | 进入所选的默认主服，与连接域名无关。主服的自动启动策略仍决定谁可以启动它。 |
| 按域名进入 | 按连接域名匹配服务器。可设置「默认目标（选填）」处理未匹配的域名；未设置时，要求网页登录的连接进入大厅，其余连接被拒绝。 |

「要求关联面板账号」开启时，玩家须在登录空间完成网页登录；关闭后仍验证游戏身份，面板账户可另行通过 `/link` 关联。

目标未运行时的处理方式：

| 选项 | 行为 |
| --- | --- |
| 自动启动并等待 | 沿用唤醒权限、维护状态、同时运行上限与冷却检查。须选择运行中的「启动等待空间」：登录空间（Limbo）或正式大厅；要求网页登录时固定使用正式大厅。未关联账户的玩家须由目标服务器的自动启动策略允许其游戏身份启动；选定为主服本身不授予启动权限。启动失败或超时时显示原因，在登录空间中等待的连接随后断开。 |
| 进入备用服务器 | 进入另一台运行中的「备用服务器」。代理不会自动启动备用服务器，两个目标都不可用时拒绝连接。 |
| 拒绝连接并说明原因 | 直接拒绝并说明原因，无需等待空间。 |

首次保存策略之前，系统使用默认策略：按域名进入、要求关联面板账号、自动启动并在正式大厅等待。

### 单服务器部署 {#single-server}

只运行一台服务器时，可让玩家直接进入该服务器：

1. 在「进入方式」中选择「直达主服」，在「默认主服」中选择该服务器。
2. 关闭「要求关联面板账号」。
3. 选择目标未运行时的处理方式。
4. 选择「保存进入策略」，并完成身份验证。

此后运行中的主服直接接收已认证的玩家，玩家无需经过登录空间或大厅。游戏身份认证与全局黑名单仍然生效；此设置不会启用离线模式，也不会改变认证源。

保存的策略在代理 15 秒内读取后用于新连接，在线玩家沿用连接时的策略。未使用的登录空间或正式大厅不会自动停止，可在「登录与大厅」中手动停止；重新运行 `felis setup` 会保留系统服务器的期望状态。使用此功能时，API 与游戏插件须为同一版本。

同一页面的「启动与唤醒策略」卡片设置同时运行的服务器上限与唤醒冷却时间，见[启动与唤醒策略](/guide/administration#wake-policy)。

## 自定义登录空间与大厅 {#customize-login-lobby}

管理员在「管理 → 登录与大厅」中自定义玩家进入时看到的场景、提示与规则。在「选择要自定义的空间」中选择「登录空间」或「正式大厅」；系统服务器的控制台页也提供「自定义登录空间」与「自定义大厅」入口。

登录空间基于 Limbo，玩家在这里完成身份验证；正式大厅基于 Paper，提供服务器选择菜单。两者都不会空闲停服。

### 设置项 {#space-settings}

设置可以在空间运行时保存，在下次启动或重启后生效。保存后选择「重启并应用」立即生效，重启会断开该空间内的玩家。设置保存在空间数据卷的 `/data/felis-experience.json` 中，与镜像无关。

正式大厅的设置：

| 分组 | 设置项（默认值） |
| --- | --- |
| 欢迎与菜单 | 中文菜单标题、英文菜单标题、中文欢迎文案、英文欢迎文案；加入时发送欢迎提示（开）；加入时自动打开服务器菜单（关）。欢迎提示附带可点击的服务器菜单。 |
| 玩家行为与保护 | 玩家默认游戏模式（冒险）；加入时回到世界出生点、禁止普通玩家破坏和建造、玩家免受伤害、禁止饥饿、掉入虚空时回到出生点（均为开）。具有建造权限的玩家保留自己的游戏模式。 |
| 世界环境 | 难度（和平）；固定时间（0–23999，默认 6000）；固定世界时间、保持晴天、死亡后保留物品、立即重生（开）；允许 PvP、允许自然生成生物、允许生物破坏、允许 TNT 爆炸、显示进度公告（关）。 |

登录空间的设置位于「登录提示与等待」分组：登录书标题、登录书作者、登录书页标题、登录链接文案、登录说明、自动打开登录书（开），以及登录等待时间（30–3600 秒，默认 600）。绑定码与登录链接由系统生成，聊天提示始终启用。部署中显式设置的环境变量 `FELIS_LOGIN_TIMEOUT_SECONDS` 优先于此处的登录等待时间。

文案最多 512 个字符。设置文件内容有误时，游戏对无法读取的部分使用默认值，页面保留仍然有效的设置，保存后覆盖该文件。

### 地图、插件与文件 {#space-content}

「内容与维护」区域提供以下入口：

- **地图与场景**：
  - 正式大厅：备份并停止大厅，在文件管理中上传世界 ZIP 并解压到根目录，确认世界目录直接包含 `level.dat`，在 `server.properties` 中设置 `level-name` 后启动。出生点使用地图中保存的位置，可在大厅控制台执行 `setworldspawn x y z` 修改。
  - 登录空间：停止登录空间，将自定义场景上传为根目录的 `spawn.schem` 后启动，出生位置在 `server.properties` 中调整。登录空间使用 Limbo schematic，不支持 Paper 世界地图与 Paper 插件。
- **插件与插件配置**：上传插件 JAR 并编辑插件配置。插件须适配该空间的核心与版本；系统自带的 Felis 插件与 LuckPerms 在启动时随镜像更新。
- **高级文件管理**：编辑服务器属性、世界配置与插件数据。认证转发设置由系统维护。
- **控制台与运行日志**：查看日志，在大厅中执行命令。Limbo 不支持 RCON 命令，登录空间的配置须通过文件管理修改。
- **地图备份与恢复**：更换地图、插件或镜像前保存备份，或选择已有备份恢复。
- **大厅建造权限**：在大厅运行时输入 Minecraft 角色名，选择「允许建造」或「禁止建造」，授予或撤销 `felis.lobby.build` 权限。该权限默认授予 OP；也可在大厅控制台执行 `lp user <名称> permission set felis.lobby.build true`。

文件管理要求空间处于停止状态。登录空间停止期间，新玩家无法进入。更换镜像时，自定义镜像须保留 Felis 登录插件或菜单插件，并支持代理的转发协议；镜像与资源可在系统服务器的「编辑服务器配置」中调整。镜像的构建与行为见[大厅镜像](/reference/lobby#customize)与[登录空间镜像](/reference/limbo#customize)。

## 全局黑名单 {#blacklist}

全局黑名单记录被禁止登录的游戏身份，按 UUID 匹配。名单中的身份在游戏代理验证身份时即被拒绝，并在登录空间中被断开，不受玩家进入策略影响；关闭「要求关联面板账号」后黑名单同样生效。由于按 UUID 匹配，与被禁身份同名但 UUID 不同的正版玩家不受影响。面板中没有编辑黑名单的页面。
