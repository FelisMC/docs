# 管理服务器 {#servers}

本页说明如何在 Felis 面板中创建与认领服务器、控制服务器的启动与休眠，以及使用控制台、玩家管理、文件管理、计划任务与备份。本页面向服务器所有者、管理员与平台所有者。

## 权限 {#permissions}

可执行的操作取决于账户角色与服务器归属。下表中“服务器所有者”指认领或创建了该服务器的账户；“所有者”指平台的所有者角色，所有者具备管理员的全部权限。

| 操作 | 可执行者 |
| --- | --- |
| 创建服务器 | 管理员；有建服配额的账户可创建归自己所有的服务器，见[自助创建](#self-service) |
| 编辑服务器配置 | 管理员；服务器所有者可修改自己的服务器，镜像除外 |
| 认领未归属的服务器 | 已关联 Minecraft 账户的账户 |
| 启动服务器 | 服务器所有者、管理员；其他玩家按[自动启动策略](#autostart)执行 |
| 停止、重启、强制结束、控制台、玩家管理、文件、计划任务、备份与恢复 | 服务器所有者、管理员 |
| 放弃服务器 | 服务器所有者、管理员 |
| 删除服务器 | 管理员 |
| 转发方式、应急停止 | 所有者 |

管理员在「服务器」页面看到平台上的全部服务器，包括所有者、在线人数与自启策略；普通用户看到自己拥有的服务器与可认领的服务器。角色说明见[角色](/guide/administration#roles)。

## 创建服务器 {#create-server}

管理员创建的服务器处于停止状态且不属于任何账户，由用户认领后归其所有，见[认领服务器](#claim)。有建服配额的账户可以创建归自己所有的服务器，见[自助创建](#self-service)。

1. 打开「服务器」，选择「新建服务器」。
2. 在「运行方式」中选择「服务端软件」或「白名单镜像」。普通账户只能选择服务端软件。
3. 填写以下字段：

   | 字段 | 说明 |
   | --- | --- |
   | 服务端软件 | 选择核心、游戏版本、构建或加载器版本与 Java 版本，见[服务端软件](/guide/software#types)。 |
   | 镜像 | 选择「白名单镜像」时，从镜像白名单中选择，见[镜像与 Minecraft 版本](#images-versions)。 |
   | 名称 | 3–32 位小写字母、数字或连字符，首尾不能为连字符。`login`、`lobby`、`admin`、`panel`、`console`、`api`、`felis`、`velocity`、`registry`、`internal`、`www` 为平台保留名称。 |
   | 子域名 | 规则与名称相同。玩家通过 `<子域名>.<根域名>` 进入该服务器。 |
   | 显示名称（选填） | 面板与大厅菜单中显示的名称。 |
   | 执行位置 | 仅管理员在多机部署中可见，选择在线且已批准的节点，见[多机部署与高可用](/guide/distributed#overview)。 |
   | 内存 | 容器内存上限，以 GiB 为单位，默认 4，可填写小数（例如 1.5），不小于 1。Java 堆内存按此自动计算。 |
   | 存储 | 世界卷容量，以 GiB 为单位的整数，默认 10，创建后不能修改。 |
   | 自动启动策略 | 默认「仅所有者——通过面板启动」，见[自动启动策略](#autostart)。 |

4. 使用服务端软件时，勾选同意 Minecraft 最终用户许可协议（EULA）。
5. 选择「创建」。

新服务器默认在无人在线 600 秒后自动停止。管理员创建的服务器不占用任何用户的配额，配额在认领时计算。名称与已删除服务器遗留的世界卷相同时，创建被拒绝，须先清理该世界卷或改用其他名称。

### 自助创建 {#self-service}

账户具备以下条件时，「服务器」页面显示「新建服务器」，账户可创建归自己所有的服务器：

- 已关联 Minecraft 账户，见[关联账户](/guide/players#account-linking)。
- 有建服配额：所有者为该账户单独设置了配额，或开启了[自助建服](/guide/administration#self-service)的默认配额。

自助创建的服务器只能使用服务端软件，资源计入账户配额；面板显示配额使用情况与剩余额度，填写的内存或存储超出剩余配额时无法创建。服务器数量达到上限时，「新建服务器」不可用。多机部署中，服务器创建在承载用户服务器最少的已批准节点上。服务器所有者可以放弃自己的服务器，删除服务器仍由管理员执行，见[放弃与删除服务器](#retire)。

### 镜像与 Minecraft 版本 {#images-versions}

使用镜像运行的服务器只能使用镜像白名单中已启用的镜像，白名单由管理员维护，见[镜像白名单](/guide/administration#images)。玩家投稿的模组包经审核与构建后也会加入白名单，见[审核提交](/guide/administration#submissions)。

- 创建服务器时，服务器固定在镜像标签当时指向的构建上。镜像标签之后指向新构建时，已有服务器保持不变。
- 在「编辑服务器配置」中更换镜像后，服务器使用该标签当前指向的构建；重新选择同一标签同样会采用其最新构建。Minecraft 版本变化可能在下次启动时升级世界，升级后的区块无法在旧版本中使用。保存前须勾选「我已备份世界，确认更换镜像」。
- 游戏代理以现代转发向服务器传递玩家身份。基于 Paper 的镜像由 Felis 在每次启动前自动写入转发配置；其他服务端须读取环境变量 `FELIS_FORWARDING_SECRET` 并自行启用 Velocity 现代转发，或改用[传统转发](#forwarding-mode)。
- 登录空间与正式大厅使用平台的 Minecraft 版本，玩家所需的客户端版本显示在「账户」页。目标服务器可能需要其他版本或模组，由服务器所有者另行说明。

## 认领服务器 {#claim}

不属于任何账户的服务器可以被认领。认领后，当前账户成为服务器所有者，获得控制台、白名单与备份管理等权限，其 Minecraft UUID 加入该服务器的访问白名单。

认领须满足以下条件：

- 账户已关联 Minecraft 账户，见[关联账户](/guide/players#account-linking)。
- 认领后的资源总量不超过账户配额，见[配额](#quotas)。
- 服务器未处于待回收或待删除状态。

认领方式：

- 在面板「服务器」中，对可认领的服务器选择「认领」并确认。
- 在游戏中进入该服务器后执行 `/felis claim`。
- 在大厅菜单中点击「认领并启动」磁贴，见[进入服务器](/guide/players#joining)。

认领失败时的错误说明见[账户关联与认领错误](/operations/troubleshooting#account-link-errors)。

## 编辑服务器配置 {#edit-server}

管理员与服务器所有者在服务器控制台页选择「编辑服务器配置」，可修改以下项目，未修改的项目保持原值：

- 显示名称与自动启动策略。
- 服务端软件，见[更换核心或版本](/guide/software#change)。
- 镜像（仅管理员），见[镜像与 Minecraft 版本](#images-versions)。
- 内存与 CPU 限制。CPU 限制填写核数（如 `1`、`1.5`）或毫核（如 `500m`），留空表示不限制。
- 空闲自动停服，见[启动、停止与休眠](#power)。
- 崩溃后自动重启与主机重启后恢复运行，见[崩溃与主机重启](#recovery)。
- 邮件通知，见[邮件通知](#notifications)。
- JVM 参数、启动参数、环境变量与停止命令，见[高级启动设置](#startup-settings)。

增加已归属服务器的 CPU 或内存时，新规格须在服务器所有者的配额内；减少规格不受配额限制。登录空间与正式大厅属于系统服务，由管理员在「登录与大厅」中管理，见[自定义登录空间与大厅](/guide/players#customize-login-lobby)。

### 高级启动设置 {#startup-settings}

服务器所有者与管理员可展开「编辑服务器配置 → 高级启动设置」，读取并修改该服务器的 JVM 参数、启动参数、环境变量与停止命令。登录空间与正式大厅由管理员管理。高级启动设置不会出现在公开服务器状态中，也不包含平台托管的环境变量。

| 设置 | 填写方式与限制 |
| --- | --- |
| JVM 参数 | 每项填写一个完整参数，最多 128 项，每项最多 1,024 字节。参数不能包含空白；禁止堆大小参数（包括 `-Xmx`、`-Xms`）与参数文件入口，堆大小由内存设置派生。 |
| 启动参数 | 每项作为一个独立参数传给服务端，保留项内空格、顺序与空字符串。最多 128 项，每项最多 2,048 字节。 |
| 环境变量 | 以名称和值逐项填写，最多 64 项。名称须唯一，只含英文字母、数字与下划线，且不能以数字开头，最多 128 字节；值最多 4,096 字节，允许为空。 |
| 停止命令 | 按填写顺序执行，最多 16 项，每项为一条不超过 1,024 字节的单行命令。首尾空白与命令开头的一个 `/` 会被移除。 |

所有高级启动设置的总大小最多为 64 KiB，按 UTF-8 字节计算。环境变量不能覆盖 `FELIS_*` 或运行时保留变量，例如 `JAVA_MEMORY`、`JAVA_FLAGS`、`JAVA_TOOL_OPTIONS`、`RCON_PASSWORD`、`PATH` 与 `HOME`。删除一项后保存会移除该项；未修改的设置保持原值。

保存 JVM 参数、启动参数与环境变量后，在下一次启动或重启时生效。运行中或启动中保存不会立即重启服务器。停止命令在下一次正常停止或显式重启时，于世界保存尝试之后、关闭进程之前通过 RCON 依次尝试执行；整组命令最多等待 30 秒。RCON 不可用、命令失败或超时不会阻止停服；故障重试时命令可能再次执行。强制结束、应急停止与启动失败后的自动重试不执行这些命令。

### 额外 TCP 与 UDP 端口 {#extra-ports}

服主与管理员可在「编辑服务器配置」的「额外端口」中添加最多五项配置，选择 TCP 或 UDP，并填写插件或模组实际监听的内部端口。内部端口范围为 1–65535，同一协议的端口不能重复；平台托管的游戏、RCON 与健康检查 TCP 端口不可暴露。

平台自动分配 30000–32767 范围内的对外端口。保存后，控制台显示协议、内部端口、对外端口和可复制的节点直连地址；IPv6 地址带方括号。插件监听内部端口，客户端连接对外端口。例如，[Simple Voice Chat](https://modrepo.de/minecraft/voicechat/wiki/server_config) 默认使用 UDP 24454，[Dynmap](https://github.com/webbukkit/dynmap/wiki/Configuration.txt#webserver-port) 使用 TCP 8123，[BlueMap](https://bluemap.bluecolored.de/wiki/FAQ.html) 使用 TCP 8100。Simple Voice Chat 的 `port` 保持为配置的内部端口，`voice_host` 填写控制台显示的完整对外地址；网页地图使用 `http://节点IP:对外端口/` 访问。

映射可在运行中或停止后修改，保存不会启动或重启游戏。插件自身配置的生效方式仍由插件决定。配置尚未完成或没有可用直连地址时，面板显示待应用或地址不可用；应等待确认后的地址再配置客户端。停止服务器不会主动释放仍保留的端口配置；删除配置后，平台撤销映射并释放相应端口。

额外连接直接到达运行服务器的节点，不经过现有 Cloudflare Tunnel 路由。安装器会在已启用的 firewalld 或 ufw 中开放默认端口范围；云安全组与 NAT 转发也须允许相应连接。迁移到其他节点后，直连 IP 可能改变，应使用控制台当前显示的地址。

### 磁盘用量与配额 {#disk-quota}

创建服务器时选择的存储大小同时作为该服务器的磁盘配额。控制台与文件页显示用量、配额和最近采样时间，停止后的服务器仍会继续统计。用量按世界卷中已分配的磁盘字节计算，包含世界、插件、配置、日志和卷内临时文件；稀疏文件按实际分配量计算，硬链接只计一次，符号链接不会被跟随。

用量达到配额的 90% 时，控制台显示提醒；启用「运行异常」邮件通知的服主也会收到通知。达到 100% 时，平台按正常流程停止服务器，记录 `DiskFull` 停止原因，并拒绝启动、重试启动和重启。文件管理与下载仍可用于清理；平台确认新的有效采样低于配额后，可再次启动，服务器不会自动恢复运行。

平台每分钟串行安排只读卷扫描。服务器较多、卷挂载较慢或目录较大时，更新可能延后；这是周期检测后的停服保护，检测和正常停服期间仍可能继续写入。扫描失败、超时或不完整时保留上次成功结果，超过三分钟的样本标为已过期。清理后，即使新样本已低于配额，也可能仍需等待平台确认，期间保留采样时间并提示当前用量不可用，启动限制继续有效。没有成功样本时显示用量不可用，不显示为零；已有的满额启动限制不会因采样失败解除。

文件列表中的「可用空间」是底层文件系统余量，与每服配额分开计算；即使用量尚未达到配额，底层存储空间不足仍可能导致写入失败。

## 启动、停止与休眠 {#power}

服务器有以下状态：

| 状态 | 说明 |
| --- | --- |
| 运行中 | 服务器已就绪，玩家可以进入。 |
| 启动中 | 正在调度资源、准备文件与拉取镜像，或正在启动 Minecraft 并检查就绪状态。 |
| 停止中 | 正在保存世界并关闭。 |
| 已停止 | 服务器处于休眠状态，不占用内存与 CPU。 |
| 启动超时·重试中 | 启动超时，系统正在重建运行实例并自动重试。 |
| 启动失败 | 自动重试次数已达上限。 |

### 启动 {#start}

服务器可通过以下方式启动：

- 在控制台页选择「启动」。
- 玩家进入服务器地址时自动唤醒，受[自动启动策略](#autostart)约束。
- 在游戏中执行 `/felis go <服务器>`，或在大厅菜单中点击服务器磁贴。
- 计划任务的启动动作，见[计划任务](#schedules)。

每次启动都受平台的同时运行服务器上限与唤醒冷却时间约束，见[启动与唤醒策略](/guide/administration#wake-policy)。待回收或待删除的服务器无法启动；备份、恢复或文件修改进行期间，启动请求被拒绝并提示服务器正在维护。

启动期间，控制台页显示当前阶段与诊断信息。可调度内存不足时，页面提示降低内存配置、停止其他服务器或增加节点容量。默认启动时限为 300 秒，超时后系统最多重建运行实例 3 次，每次之间等待时间递增；仍未就绪时状态变为「启动失败」。排除故障后选择「重试启动」。启动问题的排查见[服务器卡在启动中](/operations/troubleshooting#server-stuck-starting)与[服务器启动失败](/operations/troubleshooting#server-failed)。

### 停止与空闲自动停服 {#stop}

在控制台页选择「停止」。有玩家在线时，服务器先向在线玩家发送游戏内通知，30 秒后断开连接并停止；在此期间再次启动服务器可取消停止。在线人数无法读取时，面板提示可能仍有玩家在线并要求确认。

服务器在线人数为零且持续达到设定时长后自动停止，释放内存与 CPU，之后玩家进入时按自动启动策略唤醒。新建服务器默认 600 秒，管理员可在「编辑服务器配置 → 空闲自动停服」中修改或设为「从不」。在线人数通过 RCON 读取；无法读取时空闲停服暂停，读取恢复后继续判断。登录空间与正式大厅不会空闲停服。

### 重启 {#restart}

运行中的服务器在控制台页显示「重启」。重启会保存并关闭当前进程，再重新启动服务器；有玩家在线或在线人数无法读取时，面板要求确认。备份、恢复或文件修改等维护操作进行期间，重启请求被拒绝。

### 强制结束 {#force-stop}

服务器进程无响应或普通停止未完成时，服务器所有者与管理员可在控制台页选择「更多操作 → 强制结束」，阅读数据丢失提示后确认。强制结束会立即终止进程，不执行保存，也不等待停服倒计时或终止宽限期；在线玩家将断开连接，上次保存之后的改动可能丢失。

请求受理后，平台执行停止操作，面板继续更新服务器状态。停止操作处理完成前无法重新启动。强制结束依赖 operator；operator 无响应时，由平台所有者使用下方的应急停止。

### 应急停止 {#emergency-stop}

普通停止无响应时，所有者可执行应急停止：

1. 在服务器控制台页选择「更多操作 → 应急停止」。
2. 输入服务器名称并完成身份验证。

应急停止先保存停止意图，再将工作负载副本数直接设为零，绕过游戏进程与 operator，并保留正常的终止宽限期。世界数据不会被删除，未保存的更改可能丢失。请求被受理不代表进程已经退出，面板继续检查游戏 Pod 的状态，在 Pod 退出前显示「停止中」。

::: warning 注意
应急停止会立即断开所有在线玩家。控制 API 离线时，面板无法操作集群，展开「主机侧应急停止步骤」后在主机上依次执行其中的命令。处理控制连接中断时，不要通过强制删除世界、Pod 或 PVC 来解决。
:::

面板在 12 秒内无法读取服务器状态时，显示最后一次成功读取的时间并自动重试。此时显示的状态仅供参考，不能据此判断游戏进程是否健康。

## 崩溃与主机重启 {#recovery}

### 崩溃后自动重启 {#crash-restart}

服务器进程意外退出（包括内存不足被终止）或长时间无响应时，平台默认自动重启服务器。自动重启设有连续次数上限，避免反复崩溃的服务器无限重启：

- 连续崩溃次数未超过上限时，服务器自动重启。
- 连续崩溃次数超过上限时，服务器停止运行，控制台页显示停止原因与最近一次崩溃的原因。
- 距上一次崩溃超过 1 小时后再次崩溃，重新计数。

管理员与服务器所有者在「编辑服务器配置 → 运行与恢复」中设置：

| 设置 | 默认 | 说明 |
| --- | --- | --- |
| 崩溃后自动重启 | 开启 | 关闭后，平台在检测到进程退出时停止服务器。停止前进程可能已短暂重新启动。 |
| 最多连续重启 | 3 次 | 可设为 1 至 20 次。 |

因崩溃而停止的服务器不会被玩家进入唤醒，须由服务器所有者或管理员排除故障后在控制台页选择「启动」，启动后崩溃计数清零。在游戏内执行 `/stop` 等命令使进程退出时，平台同样视为进程意外退出；停止服务器请使用控制台页的「停止」。

控制台页的「运行记录」列出最近的启动、停止、崩溃、启动失败与主机重启事件。

### 主机重启后恢复运行 {#resume-after-host-restart}

主机断电或重启后，平台服务随主机自动启动，重启前处于运行状态的服务器默认随之恢复运行。在「编辑服务器配置 → 运行与恢复」中关闭「主机重启后恢复运行」后，该服务器在主机恢复后保持停止，控制台页显示原因；需要时选择「启动」，玩家进入时也会按自动启动策略唤醒。主机重启造成的进程退出不计入崩溃次数。

::: tip 提示
断电恢复后主机能否自动开机，取决于硬件或虚拟化平台的设置，例如 BIOS 中的“通电后开机”（Restore on AC Power Loss）。无人值守部署需在主机侧开启该设置。
:::

登录空间与正式大厅始终自动重启并在主机重启后恢复运行，不受上述设置影响，其故障由平台告警通知平台所有者，见[监控与告警](/operations/monitoring)。

## 邮件通知 {#notifications}

平台已配置[邮件服务](/guide/administration#mail-relay)时，服务器事件通过邮件发送至服务器所有者已验证的邮箱；未认领的服务器发送至平台所有者。管理员与服务器所有者在「编辑服务器配置 → 邮件通知」中选择通知的事件：

| 通知 | 默认 | 包含的事件 |
| --- | --- | --- |
| 运行异常 | 开启 | 进程崩溃及自动重启的结果、因崩溃停止、启动失败、主机重启后恢复运行或保持停止。 |
| 服务器启动 | 关闭 | 服务器启动完成。 |
| 服务器停止 | 关闭 | 服务器停止完成，包括空闲自动停服。 |

进程崩溃后，平台最多等待 3 分钟，将重启结果与期间的后续事件合并为一封邮件；因崩溃停止时立即发送。超过 1 小时仍未发出的事件不再补发。邮件计入邮件服务的每小时发信上限。登录空间与正式大厅不发送此类邮件。

## 自动启动策略 {#autostart}

自动启动策略决定谁可以唤醒处于休眠状态的服务器。服务器所有者与管理员始终可以启动服务器。

| 策略 | 可唤醒服务器的玩家 |
| --- | --- |
| 仅所有者——通过面板启动 | 仅服务器所有者与管理员。 |
| 公开——任意玩家加入即启动 | 任意玩家加入即触发启动。 |
| 唤醒名单——已加入且具有唤醒权限的玩家可启动 | 服务器所有者、管理员，以及唤醒名单中具有唤醒权限的玩家。 |

策略由管理员在「编辑服务器配置」中设置。采用「唤醒名单」策略时，玩家首次加入服务器后自动列入名单；服务器所有者或管理员在「玩家管理 → 唤醒名单」中选择「取消唤醒」撤销权限，选择「重新允许」恢复权限。被撤销的玩家再次加入不会恢复权限。服务器所有者变更后，唤醒名单清空。

玩家无权唤醒服务器时，游戏内提示其不能启动该服务器；平台达到同时运行上限时，提示稍后再试。

## 控制台 {#console}

服务器控制台页显示实时日志，并提供以下功能：

- 日志连接状态（实时、重连中、连接已断开），以及「重连」「清屏」「滚动到最新」。RCON 连接的生命周期日志默认隐藏，可通过「显示 RCON 连接日志」显示。
- 服务器启动或运行时，服务器所有者与管理员可在「服务器命令」输入框中发送控制台命令，例如 `list`、`op <玩家>`。
- 进入玩家管理、LuckPerms 权限、备份与恢复、服务器文件与计划任务等子页面。

### 发送命令 {#console-commands}

输入单行命令后按 Enter 或选择「发送命令」。RCON 可用时显示命令回复；启动期间或 RCON 连接不可用时，平台可通过服务器标准输入发送，面板提示「命令已发送，请在控制台日志查看执行结果。」该提示表示输入已发送，执行结果须以日志为准。

若发送后连接中断，面板会提示结果不确定并保留输入。请先核对日志，再决定是否重新发送，平台不会自动重发。服务器未启动或正在停止时，命令输入不可用；备份、恢复、迁移等维护期间，发送请求被拒绝。

升级前已运行的服务器在下次启动或重启时启用标准输入，升级本身不会为此重启游戏进程。旧实例尚未启用标准输入时，仍可通过可用的 RCON 发送命令。

### 停服日志 {#stopped-logs}

服务器完全停止后，服务器所有者与管理员可在控制台查看世界卷中 `logs/latest.log` 的末尾 200 行，并向前加载更早内容。每页最多显示 256 KiB；单行超过限制时分段显示。历史日志只读，服务器启动后自动连接实时日志。

世界卷或日志文件不存在时显示无历史日志。日志被替换或修改后，须刷新重新读取，避免混合不同版本的内容。备份、恢复或迁移期间遵循现有文件访问限制。

### 资源占用 {#resource-usage}

服务器所有者和管理员可在控制台查看当前 CPU、内存占用，以及最近 1 小时的曲线。宽屏服务器列表同时显示当前占用。CPU 百分比按该服务器的 CPU 限额计算，例如使用 500 毫核、限额 2 核时显示 25%；未设置 CPU 限额时显示毫核。内存显示实际工作集与容器内存限额，包含 JVM 堆以外的内存。

平台每 15 秒采样一次，每台最多保留 240 点。服务器停止或指标不可用时，当前值显示为空，已有曲线保留至 1 小时；不会将指标缺失显示为零。曲线保存在 API 实例内存中，实例重启或切换后重新累积。资源采样不包含磁盘用量与网络流量。

## 玩家管理 {#players}

「玩家管理」页面通过实时连接管理玩家，仅在服务器运行时可用，限服务器所有者与管理员使用。

- **白名单**：输入玩家 ID（1–16 位字母、数字或下划线）后选择「添加」，或选择「移除」。白名单在游戏中开启（控制台命令 `whitelist on`）时，仅名单内玩家可以进入。
- **在线玩家**：查看当前在线的玩家，选择「踢出」断开指定玩家。
- **封禁**：输入完整玩家 ID 后选择「封禁」，玩家被踢出并无法再次进入；在封禁名单中选择「解封」解除。
- **唤醒名单**：见[自动启动策略](#autostart)。

面板无法解析服务器返回的内容时，可通过「查看服务器原始返回」查看原始输出。

### LuckPerms 权限 {#luckperms}

服务器安装并运行 LuckPerms 插件时，「LuckPerms 权限」页面可管理玩家的用户组与权限节点：

1. 在左侧选择在线玩家，或在上方按名称查询玩家。
2. 选择「添加用户组」或「移除用户组」管理父组。
3. 填写权限节点、权限值（允许或拒绝）与可选的世界范围，选择「添加权限」或「移除权限」。移除操作删除指定世界范围内的该节点，与其值无关。

页面提供常用预设，并在「最近操作历史」中保留操作记录，可选择「撤销」回退。按玩家名操作仅对安装 LuckPerms 后加入过服务器的玩家可靠。

## 已装插件与模组 {#extensions}

服务器所有者与管理员可从控制台侧栏进入「插件与模组」，查看 `plugins/` 和 `mods/` 目录中的 `.jar` 与 `.jar.disabled` 文件。服务器运行中或完全停止时均可使用；启动、停止或维护期间须等待相应操作完成。

列表显示文件名、大小、启用状态，以及清单声明的名称、版本、作者与适用加载器。支持 Bukkit、Paper、Fabric、Quilt、Forge、NeoForge 和 Velocity 的清单；一个 JAR 包含多个模组或支持多个加载器时，会保留各项声明。无法读取元数据的文件仍会显示，可以禁用或删除。实际加载状态以服务器控制台为准。

- **启用与禁用**：在 `.jar` 与 `.jar.disabled` 之间重命名。目标文件已存在时不会覆盖，须先在文件管理中处理重名文件。
- **删除**：确认后永久删除所选 JAR，配置文件保留。
- **打开配置目录**：进入文件管理中的现有配置目录。未发现对应目录时不显示此入口。
- **上传 JAR**：选择插件或模组目录，沿用文件管理的上传队列与大文件分片。上传整批文件后刷新列表。

运行中上传、启用、禁用或删除后，重启服务器应用更改。修改世界目录仍须额外勾选确认，包括将 `level-name` 设置为 `plugins` 或 `mods` 的情况。目录不存在时列表为空；每个目录最多扫描 2000 项，列表最多返回 500 个文件，并限制响应与清单大小，达到上限时会提示通过文件管理查看其余文件。

## 服务器文件 {#files}

「服务器文件」页面用于浏览和修复世界卷中的文件，限服务器所有者与管理员使用。服务器运行中或完全停止时均可使用；正在启动或停止时，须等待状态切换完成。新建且尚未启动过的服务器同样可以使用，例如在首次启动前放入整合包、世界或自定义 jar。

运行中访问文件时，页面显示风险提示：世界文件的改动可能被服务器覆盖，插件与配置的改动通常在重启后生效。修改 `world`、`world_nether`、`world_the_end` 或 `server.properties` 中 `level-name` 指定的世界目录前，须额外勾选风险确认项；运行中解压归档也需要此确认。确认仅对当前页面有效，重新打开页面或服务器切换运行状态后须重新确认。

可执行的操作：

- 浏览目录，新建文件或文件夹，重命名与删除。勾选多项后可批量删除或打包下载。删除不可恢复，请先备份需要保留的内容。每行的「更多」菜单也支持鼠标右键与移动端长按。
- 在同一服务器内复制或剪切文件与文件夹，再进入目标目录粘贴。目标存在同名文件时，先查看冲突列表，再确认是否覆盖；文件与文件夹类型冲突时须先调整名称。
- 按文件名搜索当前目录及其子目录，最多显示 500 条结果，递归深度最多 16 层，并跳过 `region`、`entities`、`poi` 区块数据目录。结果被截断时，可缩小目录或增加搜索条件。
- 在线编辑不超过 5 MiB 的文本文件，保留 CRLF 换行。二进制文件与超出上限的文件请下载后处理再上传。文件在打开后被修改时，编辑器提示选择「载入最新内容」或「仍然覆盖」。
- 上传文件或文件夹：使用上传按钮选择，或将文件、文件夹拖入列表。文件夹保留相对目录结构，逐文件创建目录并上传。不超过 64 MiB 的文件一次上传，更大的文件由面板自动分片上传，每片 32 MiB，中断后可续传。同名文件可选择「替换」或「跳过」。每个账户最多同时进行 4 个大文件上传，6 小时无进展的上传会话被丢弃。
- 从公开网址下载文件到指定路径。仅支持不含用户名与密码的 HTTP、HTTPS 地址；内网、回环、链路本地地址与重定向到这些地址的请求会被拒绝。文件先下载到平台暂存盘，再写入服务器，大小受暂存盘可用空间约束。
- 将选中项打包为服务器上的 `.zip` 文件，或解压 `.zip`、`.tar`、`.tar.gz`、`.tgz` 到当前目录。解压前检查越界路径、链接、文件与文件夹类型冲突及剩余空间；会覆盖现有文件时，面板列出冲突文件供确认。使用 GBK 编码文件名的 zip 压缩包可正常解压。
- 下载文件，或将文件夹及多个选中项打包为 `.zip` 下载。每个账户最多同时 2 个下载、每小时 30 个，平台最多同时 4 个。不超过 5 MiB 的 PNG、JPG、GIF、WebP 图片可以直接预览，预览使用同一下载通道并计入下载限额。

上传落盘、复制、移动、打包与解压在后台执行，关闭页面后继续进行，「后台操作」显示进度，单项操作最长 2 小时。从网址下载须先等待远程内容进入暂存盘，再启动后台落盘任务。备份、恢复或迁移期间，文件操作被拒绝。服务器停止时的文件写入或下载持有维护锁，完成前无法启动；运行中的文件操作不取得该锁，也不阻止停止服务器。

运行中的服务器可能在文件操作期间重新创建源文件或目标文件。操作无法完整回滚时，「后台操作」会列出保留目录的位置；检查 `move-recovery-*` 或 `file-recovery-*` 中的内容后再移动或删除。并发新建的内容不会被自动覆盖，受保护的备份须由主机管理员恢复。

以下文件受保护：

- `config/paper-global.yml` 包含所有服务器共享的代理转发密钥，原文读取与下载受保护，下载文件夹时也会被排除。其常用配置可通过下方的受限表单编辑。
- 下载、打包或复制 `server.properties` 时，其中的凭据会被隐藏。
- `server.properties`、`config` 与 `config/paper-global.yml` 由 Felis 管理，不能重命名或移动。

### 配置文件表单 {#server-properties}

在文件管理中打开根目录的 `server.properties`，可在「表单」与「文本」之间切换。表单按游戏规则、玩家、世界、网络与性能组织常用设置，提供布尔、整数、选项与文本控件，并显示字段说明和校验错误。其他设置可在文本模式中编辑。

两个模式共用同一份草稿，切换时保留尚未保存的修改。表单只更新实际修改的属性，保留注释、顺序、未知键和换行；文件中缺少的属性不会因打开表单而自动写入。旧版使用的 PVP、下界和生物生成等属性仅在原文件包含该键时显示，并注明适用版本。托管的端口、身份验证和 RCON 等字段在表单中只读，登录空间的转发与人数设置也由平台管理。

编辑器隐藏 `rcon.password` 与 `forwarding-secrets` 的值。保存时保留未修改占位符所对应的磁盘原值，无须输入这些凭据。

`bukkit.yml`、`spigot.yml`、`config/paper-world-defaults.yml` 与 `purpur.yml` 也提供表单与文本模式。表单按各文件列出已有且类型兼容的常用项，不补默认值或创建世界覆盖设置。修改时保留注释、顺序和未知数据，排版可能被规范化；无变化时保留原文。包含锚点、别名或多文档等复杂结构时，可使用文本模式。

`config/paper-global.yml` 使用受限表单，只开放文件中已有且类型兼容的常用字段，不补默认值；代理转发和身份验证由平台托管。该表单仅获取可编辑字段，保存时仅更新实际修改的项，保留其余配置与注释。发生冲突后选择「仍然覆盖」时，会先获取最新版本，再应用这些修改。

保存前若文件已被其他进程修改，可选择「载入最新内容」或「仍然覆盖」。运行中保存配置后通常须重启服务器使其生效，相关文件访问与世界目录确认规则保持一致。

### 导入世界 {#import-world}

1. 备份并停止服务器。
2. 将世界文件夹压缩为 `.zip`，在「服务器文件」中上传到根目录。
3. 解压压缩包，确认世界目录直接包含 `level.dat`。
4. 在 `server.properties` 中将 `level-name` 设为该世界目录的名称。
5. 启动服务器。

文件操作被拒绝时的错误说明见[文件管理错误](/operations/troubleshooting#file-manager-errors)。

## 计划任务 {#schedules}

「计划任务」页面按计划执行一组服务器操作，限服务器所有者与管理员使用，每台服务器最多 20 个任务。页面提供「每天 04:00 重启」「每天 05:00 备份」「每 30 分钟在聊天栏发公告」等模板，也可选择「新建任务」自定义。

一个任务由 1 至 10 个按顺序执行的步骤组成。步骤可添加、删除和调整顺序，编辑器还提供「提醒后重启」（命令 → 延时 60 秒 → 重启）、「停服备份后启动」（停止 → 备份 → 启动）和「保存后备份」（`save-all` → 备份）三个模板，一键填入步骤。

| 步骤 | 服务器运行时 | 服务器停止时 |
| --- | --- | --- |
| 控制台命令 | 通过 RCON 执行命令，开头的 `/` 可省略；命令为单行，不超过 1024 字节 | 整次执行记为跳过 |
| 延时 | 等待 1 至 3600 秒 | 等待 1 至 3600 秒 |
| 启动 | 视为目标已成立 | 启动服务器，受同时运行上限约束 |
| 停止 | 关闭服务器，在线玩家被断开 | 视为目标已成立 |
| 重启 | 关闭后重新启动，在线玩家被断开 | 视为目标已成立 |
| 强制结束 | 立即终止服务器进程，不执行保存，在线玩家被断开 | 视为目标已成立 |
| 备份 | 优先以不停服方式备份；无法不停服备份时，先停止服务器，备份后重新启动 | 直接备份，完成后保持停止 |

任务至少包含一个非延时步骤，最多包含一个备份步骤。

任务设置项：

- **执行方式**：「每天一次」在指定时间执行；「循环执行」从每天 00:00 起按间隔执行，间隔为 1、5、10、15、30 分钟或 1、2、3、4、6、8、12 小时，包含启动、停止、重启、强制结束或备份步骤的任务，间隔不能短于 1 小时；「只执行一次」在所选日期和时间执行一次，日期时间按任务的时区解释，启用时须是将来的时间，执行后任务自动停用。
- **执行日期**：选择星期，可快速选择每天、工作日或周末。一次性任务没有该项。
- **时区**：使用 IANA 时区名称（如 `Asia/Shanghai`），默认为浏览器时区。
- **执行 N 次后停用**：1 至 10000 次；留空或填写 `0` 表示不限次数。手动「立即执行」计入次数，错过的执行不计入。达到次数后任务自动停用；重新启用已停用的任务时，已执行次数归零。启用状态下，上限须大于已执行的次数。
- **提醒玩家**：任务包含停止、重启、强制结束或备份步骤时，可在任务开始前 1、5、10、15 或 30 分钟，于服务器运行时在游戏聊天栏发送中英双语提醒。提醒发生在第一个步骤之前，措辞按第一个停止、重启、强制结束或备份步骤确定。
- **启用**：关闭后任务保留，但不再自动执行。

任务列表显示每个任务的步骤摘要（例如「控制台命令 → 延时 60 秒 → 重启」）、一次性任务的执行时间，以及限次任务已执行的次数（例如「已执行 3/10 次」）。任务执行期间，所在行显示当前进度，例如「第 2/3 步：等待服务器停止…」。

执行规则：

- felis-api 每 15 秒检查一次，任务在设定时间后约 15 秒内开始。晚于计划 10 分钟以上的执行（例如 felis-api 当时未运行）记为「错过」，下一次照常执行。
- 步骤按顺序执行。某一步失败时，整次执行记为「失败」，后续步骤不再执行；如果本次执行停止了原本在运行的服务器，失败后会将其重新启动。结果未知的命令不会自动重发。
- 启动或重启之后还有后续步骤时，先等待服务器就绪，最长 15 分钟；停止或强制结束之后还有后续步骤时，先等待服务器完全停止。
- 启动、停止、重启和强制结束在目标已经成立时（例如服务器已停止时执行「停止」或「重启」）：只有这一步的任务记为「已跳过」，多步骤任务直接进入下一步。命令步骤遇到未运行的服务器时，整次执行记为「已跳过」。
- 结果显示为「成功」「已跳过」「失败」或「错过」，并附带说明。
- 「立即执行」对已停用的任务同样有效，不发送提醒，在线玩家被立即断开，下次计划执行时间保持不变。任务执行期间不能编辑、删除或再次执行。
- 服务器所有者变更后，关联任务自动停用；新所有者确认配置并重新保存后恢复。
- 夏令时切换跳过的时间点提前一小时执行；重复的时间点只执行一次。主机无法识别的时区按 UTC 执行。
- 删除服务器时一并删除其任务。

任务被跳过或失败时的说明见[计划任务错误](/operations/troubleshooting#schedule-errors)。

## 备份与恢复 {#server-backups}

「备份与恢复」页面列出服务器的世界备份，限服务器所有者与管理员使用。备份包含服务器的完整数据卷，即世界、配置、插件与模组。

系统自动创建以下备份：

- **定时备份**：当天有玩家进入过的服务器每天生成一个恢复点，运行中的服务器以不停服方式生成。默认每台服务器保留 7 个，保存 90 天。
- **回收归档**：服务器被放弃、删除或因长期闲置被回收前，先归档世界。

手动操作：

- **立即备份**：已停止的服务器直接归档。运行中的服务器以不停服方式备份，复制世界期间存档暂停数秒，玩家保持在线；不停服备份需要服务器的 RCON 可用。服务器正在启动或停止时，须等其运行或完全停止后再备份。默认每台服务器保留最近 5 个手动备份，保存 30 天，两次手动备份至少间隔 10 分钟，管理员不受间隔限制。
- **恢复此备份**：恢复会停止服务器（有玩家在线时提前 30 秒通知），并用所选备份覆盖当前世界。建议勾选「先为当前世界做安全快照（推荐）」：快照成功后才开始恢复，快照失败则不恢复。需要撤销恢复结果时，恢复「恢复前快照」即可，系统保留最近 3 个恢复前快照。
- **下载备份**：以 `.tar.gz` 格式下载，传输过程按备份时记录的 sha256 校验。
- **导出世界**：须先停止服务器。当前世界打包为 `.tar.gz` 后自动开始下载，下载结束前服务器无法启动，请保持页面打开。
- **删除备份**：备份立即从列表中移除且不再可用于恢复，归档文件在下一次每日清理时删除，异地副本在下一次同步时删除。

回读校验失败的备份标记为「已损坏」，无法完整恢复。「最近操作」列出备份、恢复与导出任务及其失败原因。备份存储达到上限时，服务器所有者的手动备份被拒绝。

::: warning 注意
未勾选安全快照时，恢复会直接覆盖当前世界，没有其他备份的现有数据将无法找回。
:::

保留策略、不停服备份与恢复点的详细说明见[世界备份](/operations/backup#world-backups)、[不停服备份](/operations/backup#live-backups)与[每日恢复点](/operations/backup#restore-points)。备份失败的排查见[备份失败](/operations/troubleshooting#backup-failures)。

## 转发方式 {#forwarding-mode}

转发方式决定游戏代理如何向服务器传递玩家身份。所有者在服务器控制台页的「转发方式」中设置，登录空间与正式大厅不提供此设置。

| 方式 | 适用场景 |
| --- | --- |
| 现代转发 | 默认方式。1.13 及以上版本的服务器使用以代理密钥签名的现代转发。 |
| 传统转发（BungeeCord） | 通过 ViaVersion 接入的旧版本后端。 |

1. 打开服务器控制台页的「转发方式」。
2. 勾选或取消「使用传统转发」，选择「保存」。
3. 完成身份验证。代理在下次刷新服务器列表时生效，约 15 秒内。

::: warning 注意
使用传统转发的服务器信任到达其端口的任何身份。Felis 仅允许代理访问游戏服务器，请勿以其他方式暴露该服务器端口。
:::

此操作由主机节点操作服务执行并记入审计日志。安装时通过 `FELIS_LEGACY_FORWARDING_SERVERS` 指定的服务器（默认 `legacy18`）始终使用传统转发。

## 放弃与删除服务器 {#retire}

服务器所有者可以放弃服务器，管理员还可以删除服务器：

| 操作 | 结果 |
| --- | --- |
| 放弃服务器 | 世界归档后删除世界存储，服务器释放给其他账户认领。 |
| 删除服务器 | 世界归档后删除世界存储与服务器记录，名称与子域名可重新使用。 |

1. 在服务器控制台页的「放弃服务器」卡片中选择「放弃服务器」或「删除服务器」。
2. 输入服务器名称并确认。

提交后服务器进入停止流程，在下一次每日回收时处理；处理完成前服务器保持停止且无法启动。归档默认保留 90 天。处理前可在控制台选择「撤销」取消请求；由管理员提出的删除只能由管理员撤销。放弃的服务器在处理完成前仍计入账户配额。

启用世界回收后，超过 15 天无人游玩的世界会在备份后被删除，见[世界回收](/operations/backup#world-cleanup)。

## 配额 {#quotas}

所有者可为每个账户设置配额，限制其拥有的服务器数量以及 CPU、内存与存储总量；开启[自助建服](/guide/administration#self-service)后，未单独设置配额的账户使用默认配额。配额在以下情况下检查：

- 自助创建服务器时，按所选规格计算。
- 认领服务器时，按该服务器的实际规格计算。
- 增加已归属服务器的 CPU 或内存时。
- 通过账户迁移接收服务器时。

超出配额的操作被拒绝。降低配额只限制后续操作，不影响已有服务器。配额的设置方法见[配额](/guide/administration#quotas)。
