# 管理服务器 {#servers}

本页说明如何在 Felis 面板中创建与认领服务器、控制服务器的启动与休眠，以及使用控制台、玩家管理、文件管理、计划任务与备份。本页面向服务器所有者、管理员与平台所有者。

## 权限 {#permissions}

可执行的操作取决于账户角色与服务器归属。下表中“服务器所有者”指认领或创建了该服务器的账户；“所有者”指平台的所有者角色，所有者具备管理员的全部权限。

| 操作 | 可执行者 |
| --- | --- |
| 创建服务器 | 管理员；有建服配额的账户可创建归自己所有的服务器，见[自助创建](#self-service) |
| 编辑服务器配置 | 管理员；服务器所有者可修改自己的服务器，镜像除外 |
| 认领未归属的服务器 | 已关联 Minecraft 账户的账户 |
| 启动服务器 | 服务器所有者、管理员；其他玩家按[自动启动策略](#autostart)执行 |
| 停止、控制台、玩家管理、文件、计划任务、备份与恢复 | 服务器所有者、管理员 |
| 放弃服务器 | 服务器所有者、管理员 |
| 删除服务器 | 管理员 |
| 转发方式、应急停止 | 所有者 |

管理员在「服务器」页面看到平台上的全部服务器，包括所有者、在线人数与自启策略；普通用户看到自己拥有的服务器与可认领的服务器。角色说明见[角色](/guide/administration#roles)。

## 创建服务器 {#create-server}

管理员创建的服务器处于停止状态且不属于任何账户，由用户认领后归其所有，见[认领服务器](#claim)。有建服配额的账户可以创建归自己所有的服务器，见[自助创建](#self-service)。

1. 打开「服务器」，选择「新建服务器」。
2. 在「运行方式」中选择「服务端软件」或「白名单镜像」。普通账户只能选择服务端软件。
3. 填写以下字段：

   | 字段 | 说明 |
   | --- | --- |
   | 服务端软件 | 选择核心、游戏版本、构建或加载器版本与 Java 版本，见[服务端软件](/guide/software#types)。 |
   | 镜像 | 选择「白名单镜像」时，从镜像白名单中选择，见[镜像与 Minecraft 版本](#images-versions)。 |
   | 名称 | 3–32 位小写字母、数字或连字符，首尾不能为连字符。`login`、`lobby`、`admin`、`panel`、`console`、`api`、`felis`、`velocity`、`registry`、`internal`、`www` 为平台保留名称。 |
   | 子域名 | 规则与名称相同。玩家通过 `<子域名>.<根域名>` 进入该服务器。 |
   | 显示名称（选填） | 面板与大厅菜单中显示的名称。 |
   | 执行位置 | 仅管理员在多机部署中可见，选择在线且已批准的节点，见[多机部署与高可用](/guide/distributed#overview)。 |
   | 内存 | 2Gi、4Gi（默认）、6Gi 或 8Gi，同时作为 Java 堆内存与容器内存上限。 |
   | 存储 | 世界卷容量：5Gi、10Gi（默认）、20Gi 或 50Gi。 |
   | 自动启动策略 | 默认「仅所有者——通过面板启动」，见[自动启动策略](#autostart)。 |

4. 使用服务端软件时，勾选同意 Minecraft 最终用户许可协议（EULA）。
5. 选择「创建」。

新服务器默认在无人在线 600 秒后自动停止。管理员创建的服务器不占用任何用户的配额，配额在认领时计算。名称与已删除服务器遗留的世界卷相同时，创建被拒绝，须先清理该世界卷或改用其他名称。

### 自助创建 {#self-service}

账户具备以下条件时，「服务器」页面显示「新建服务器」，账户可创建归自己所有的服务器：

- 已关联 Minecraft 账户，见[关联账户](/guide/players#account-linking)。
- 有建服配额：所有者为该账户单独设置了配额，或开启了[自助建服](/guide/administration#self-service)的默认配额。

自助创建的服务器只能使用服务端软件，资源计入账户配额；面板显示配额使用情况，超出剩余配额的内存与存储规格不可选择。服务器数量达到上限时，「新建服务器」不可用。多机部署中，服务器创建在承载用户服务器最少的已批准节点上。服务器所有者可以放弃自己的服务器，删除服务器仍由管理员执行，见[放弃与删除服务器](#retire)。

### 镜像与 Minecraft 版本 {#images-versions}

使用镜像运行的服务器只能使用镜像白名单中已启用的镜像，白名单由管理员维护，见[镜像白名单](/guide/administration#images)。玩家投稿的模组包经审核与构建后也会加入白名单，见[审核提交](/guide/administration#submissions)。

- 创建服务器时，服务器固定在镜像标签当时指向的构建上。镜像标签之后指向新构建时，已有服务器保持不变。
- 在「编辑服务器配置」中更换镜像后，服务器使用该标签当前指向的构建；重新选择同一标签同样会采用其最新构建。Minecraft 版本变化可能在下次启动时升级世界，升级后的区块无法在旧版本中使用。保存前须勾选「我已备份世界，确认更换镜像」。
- 游戏代理以现代转发向服务器传递玩家身份。基于 Paper 的镜像由 Felis 在每次启动前自动写入转发配置；其他服务端须读取环境变量 `FELIS_FORWARDING_SECRET` 并自行启用 Velocity 现代转发，或改用[传统转发](#forwarding-mode)。
- 登录空间与正式大厅使用平台的 Minecraft 版本，玩家所需的客户端版本显示在「账户」页。目标服务器可能需要其他版本或模组，由服务器所有者另行说明。

## 认领服务器 {#claim}

不属于任何账户的服务器可以被认领。认领后，当前账户成为服务器所有者，获得控制台、白名单与备份管理等权限，其 Minecraft UUID 加入该服务器的访问白名单。

认领须满足以下条件：

- 账户已关联 Minecraft 账户，见[关联账户](/guide/players#account-linking)。
- 认领后的资源总量不超过账户配额，见[配额](#quotas)。
- 服务器未处于待回收或待删除状态。

认领方式：

- 在面板「服务器」中，对可认领的服务器选择「认领」并确认。
- 在游戏中进入该服务器后执行 `/felis claim`。
- 在大厅菜单中点击「认领并启动」磁贴，见[进入服务器](/guide/players#joining)。

认领失败时的错误说明见[账户关联与认领错误](/operations/troubleshooting#account-link-errors)。

## 编辑服务器配置 {#edit-server}

管理员与服务器所有者在服务器控制台页选择「编辑服务器配置」，可修改以下项目，未修改的项目保持原值：

- 显示名称与自动启动策略。
- 服务端软件，见[更换核心或版本](/guide/software#change)。
- 镜像（仅管理员），见[镜像与 Minecraft 版本](#images-versions)。
- 内存与 CPU 限制。CPU 限制填写核数（如 `1`、`1.5`）或毫核（如 `500m`），留空表示不限制。
- 空闲自动停服，见[启动、停止与休眠](#power)。

增加已归属服务器的 CPU 或内存时，新规格须在服务器所有者的配额内；减少规格不受配额限制。登录空间与正式大厅属于系统服务，由管理员在「登录与大厅」中管理，见[自定义登录空间与大厅](/guide/players#customize-login-lobby)。

## 启动、停止与休眠 {#power}

服务器有以下状态：

| 状态 | 说明 |
| --- | --- |
| 运行中 | 服务器已就绪，玩家可以进入。 |
| 启动中 | 正在调度资源、准备文件与拉取镜像，或正在启动 Minecraft 并检查就绪状态。 |
| 停止中 | 正在保存世界并关闭。 |
| 已停止 | 服务器处于休眠状态，不占用内存与 CPU。 |
| 启动超时·重试中 | 启动超时，系统正在重建运行实例并自动重试。 |
| 启动失败 | 自动重试次数已达上限。 |

### 启动 {#start}

服务器可通过以下方式启动：

- 在控制台页选择「启动」。
- 玩家进入服务器地址时自动唤醒，受[自动启动策略](#autostart)约束。
- 在游戏中执行 `/felis go <服务器>`，或在大厅菜单中点击服务器磁贴。
- 计划任务的启动动作，见[计划任务](#schedules)。

每次启动都受平台的同时运行服务器上限与唤醒冷却时间约束，见[启动与唤醒策略](/guide/administration#wake-policy)。待回收或待删除的服务器无法启动；备份、恢复或文件修改进行期间，启动请求被拒绝并提示服务器正在维护。

启动期间，控制台页显示当前阶段与诊断信息。可调度内存不足时，页面提示降低内存配置、停止其他服务器或增加节点容量。默认启动时限为 300 秒，超时后系统最多重建运行实例 3 次，每次之间等待时间递增；仍未就绪时状态变为「启动失败」。排除故障后选择「重试启动」。启动问题的排查见[服务器卡在启动中](/operations/troubleshooting#server-stuck-starting)与[服务器启动失败](/operations/troubleshooting#server-failed)。

### 停止与空闲自动停服 {#stop}

在控制台页选择「停止」。有玩家在线时，服务器先向在线玩家发送游戏内通知，30 秒后断开连接并停止；在此期间再次启动服务器可取消停止。在线人数无法读取时，面板提示可能仍有玩家在线并要求确认。

服务器在线人数为零且持续达到设定时长后自动停止，释放内存与 CPU，之后玩家进入时按自动启动策略唤醒。新建服务器默认 600 秒，管理员可在「编辑服务器配置 → 空闲自动停服」中修改或设为「从不」。在线人数通过 RCON 读取；无法读取时空闲停服暂停，读取恢复后继续判断。登录空间与正式大厅不会空闲停服。

### 应急停止 {#emergency-stop}

普通停止无响应时，所有者可执行应急停止：

1. 在服务器控制台页选择「更多操作 → 应急停止」。
2. 输入服务器名称并完成身份验证。

应急停止先保存停止意图，再将工作负载副本数直接设为零，绕过游戏进程与 operator，并保留正常的终止宽限期。世界数据不会被删除，未保存的更改可能丢失。请求被受理不代表进程已经退出，面板继续检查游戏 Pod 的状态，在 Pod 退出前显示「停止中」。

::: warning 注意
应急停止会立即断开所有在线玩家。控制 API 离线时，面板无法操作集群，展开「主机侧应急停止步骤」后在主机上依次执行其中的命令。处理控制连接中断时，不要通过强制删除世界、Pod 或 PVC 来解决。
:::

面板在 12 秒内无法读取服务器状态时，显示最后一次成功读取的时间并自动重试。此时显示的状态仅供参考，不能据此判断游戏进程是否健康。

## 自动启动策略 {#autostart}

自动启动策略决定谁可以唤醒处于休眠状态的服务器。服务器所有者与管理员始终可以启动服务器。

| 策略 | 可唤醒服务器的玩家 |
| --- | --- |
| 仅所有者——通过面板启动 | 仅服务器所有者与管理员。 |
| 公开——任意玩家加入即启动 | 任意玩家加入即触发启动。 |
| 唤醒名单——已加入且具有唤醒权限的玩家可启动 | 服务器所有者、管理员，以及唤醒名单中具有唤醒权限的玩家。 |

策略由管理员在「编辑服务器配置」中设置。采用「唤醒名单」策略时，玩家首次加入服务器后自动列入名单；服务器所有者或管理员在「玩家管理 → 唤醒名单」中选择「取消唤醒」撤销权限，选择「重新允许」恢复权限。被撤销的玩家再次加入不会恢复权限。服务器所有者变更后，唤醒名单清空。

玩家无权唤醒服务器时，游戏内提示其不能启动该服务器；平台达到同时运行上限时，提示稍后再试。

## 控制台 {#console}

服务器控制台页显示实时日志，并提供以下功能：

- 日志连接状态（实时、重连中、连接已断开），以及「重连」「清屏」「滚动到最新」。RCON 连接的生命周期日志默认隐藏，可通过「显示 RCON 连接日志」显示。
- 服务器运行时，在「服务器命令」输入框中执行控制台命令，例如 `list`、`op <玩家>`。
- 进入玩家管理、LuckPerms 权限、备份与恢复、服务器文件与计划任务等子页面。

服务器未运行时控制台不连接，启动后自动连接。

## 玩家管理 {#players}

「玩家管理」页面通过实时连接管理玩家，仅在服务器运行时可用，限服务器所有者与管理员使用。

- **白名单**：输入玩家 ID（1–16 位字母、数字或下划线）后选择「添加」，或选择「移除」。白名单在游戏中开启（控制台命令 `whitelist on`）时，仅名单内玩家可以进入。
- **在线玩家**：查看当前在线的玩家，选择「踢出」断开指定玩家。
- **封禁**：输入完整玩家 ID 后选择「封禁」，玩家被踢出并无法再次进入；在封禁名单中选择「解封」解除。
- **唤醒名单**：见[自动启动策略](#autostart)。

面板无法解析服务器返回的内容时，可通过「查看服务器原始返回」查看原始输出。

### LuckPerms 权限 {#luckperms}

服务器安装并运行 LuckPerms 插件时，「LuckPerms 权限」页面可管理玩家的用户组与权限节点：

1. 在左侧选择在线玩家，或在上方按名称查询玩家。
2. 选择「添加用户组」或「移除用户组」管理父组。
3. 填写权限节点、权限值（允许或拒绝）与可选的世界范围，选择「添加权限」或「移除权限」。移除操作删除指定世界范围内的该节点，与其值无关。

页面提供常用预设，并在「最近操作历史」中保留操作记录，可选择「撤销」回退。按玩家名操作仅对安装 LuckPerms 后加入过服务器的玩家可靠。

## 服务器文件 {#files}

「服务器文件」页面用于浏览和修复世界卷中的文件，限服务器所有者与管理员使用。运行中的服务器独占挂载世界卷，浏览或编辑文件前须完全停止服务器。

可执行的操作：

- 浏览目录，新建文件或文件夹，重命名与删除。删除不可恢复，请先备份需要保留的内容。
- 在线编辑文本文件。编辑器最多读取 1 MiB、保存 256 KiB，保留 CRLF 换行。二进制文件与超出上限的文件请下载后处理再上传。文件在打开后被修改时，编辑器提示选择「载入最新内容」或「仍然覆盖」。
- 上传文件：选择「上传」或将文件拖入列表。不超过 64 MiB 的文件一次上传，更大的文件由面板自动分片上传，每片 32 MiB，中断后可续传。文件夹须先压缩为 `.zip` 再上传并解压。同名文件可选择「替换」或「跳过」。每个账户最多同时进行 4 个大文件上传，6 小时无进展的上传会话被丢弃。
- 解压 `.zip` 文件到当前目录。解压前检查越界路径、符号链接、文件与文件夹类型冲突及剩余空间；会覆盖现有文件时，面板列出冲突文件，确认后选择「覆盖并解压」。解压失败时不修改任何文件。使用 GBK 编码文件名的压缩包可正常解压。
- 下载文件，或将文件夹打包为 `.zip` 下载。每个账户最多同时 2 个下载、每小时 30 个，平台最多同时 4 个。

大文件上传与解压在后台执行，关闭页面后继续进行，「后台操作」显示进度，单项操作最长 2 小时。文件修改、备份、恢复或下载进行期间，服务器无法启动。

以下文件受保护：

- `config/paper-global.yml` 包含所有服务器共享的代理转发密钥，不能在线读取、编辑或下载，下载文件夹时也会被排除。
- 下载 `server.properties` 时，其中的 `rcon.password` 被隐去。
- `server.properties`、`config` 与 `config/paper-global.yml` 由 Felis 管理，不能重命名或移动。

### 导入世界 {#import-world}

1. 备份并停止服务器。
2. 将世界文件夹压缩为 `.zip`，在「服务器文件」中上传到根目录。
3. 解压压缩包，确认世界目录直接包含 `level.dat`。
4. 在 `server.properties` 中将 `level-name` 设为该世界目录的名称。
5. 启动服务器。

文件操作被拒绝时的错误说明见[文件管理错误](/operations/troubleshooting#file-manager-errors)。

## 计划任务 {#schedules}

「计划任务」页面按计划执行服务器操作，限服务器所有者与管理员使用，每台服务器最多 20 个任务。页面提供「每天 04:00 重启」「每天 05:00 备份」「每 30 分钟在聊天栏发公告」等模板，也可选择「新建任务」自定义。

| 任务类型 | 服务器运行时 | 服务器停止时 |
| --- | --- | --- |
| 控制台命令 | 通过 RCON 执行命令，开头的 `/` 可省略 | 跳过 |
| 重启 | 关闭后重新启动，在线玩家被断开 | 跳过 |
| 关闭 | 关闭服务器，在线玩家被断开 | 跳过 |
| 启动 | 跳过 | 启动服务器，受同时运行上限约束 |
| 备份 | 优先以不停服方式备份；无法不停服备份时，先停止服务器，备份后重新启动 | 直接备份，完成后保持停止 |

任务设置项：

- **执行方式**：「每天一次」在指定时间执行；「循环执行」从每天 00:00 起按间隔执行，间隔为 15 分钟、30 分钟或 1、2、3、4、6、8、12 小时。重启、关闭、启动与备份最多每小时执行一次。
- **执行日期**：选择星期，可快速选择每天、工作日或周末。
- **时区**：使用 IANA 时区名称（如 `Asia/Shanghai`），默认为浏览器时区。
- **提醒玩家**：重启、关闭与备份可在执行前 1、5、10、15 或 30 分钟，于服务器运行时在游戏聊天栏发送中英双语提醒。
- **启用**：关闭后任务保留，但不再自动执行。

执行规则：

- felis-api 每 15 秒检查一次，任务在设定时间后约 15 秒内开始。晚于计划 10 分钟以上的执行（例如 felis-api 当时未运行）记为「错过」，下一次照常执行。
- 结果显示为「成功」「已跳过」「失败」或「错过」，并附带说明。
- 「立即执行」对已停用的任务同样有效，不发送提醒，在线玩家被立即断开，下次计划执行时间保持不变。任务执行期间不能编辑、删除或再次执行。
- 服务器所有者变更后，关联任务自动停用；新所有者确认配置并重新保存后恢复。
- 夏令时切换跳过的时间点提前一小时执行；重复的时间点只执行一次。主机无法识别的时区按 UTC 执行。
- 删除服务器时一并删除其任务。

任务被跳过或失败时的说明见[计划任务错误](/operations/troubleshooting#schedule-errors)。

## 备份与恢复 {#server-backups}

「备份与恢复」页面列出服务器的世界备份，限服务器所有者与管理员使用。备份包含服务器的完整数据卷，即世界、配置、插件与模组。

系统自动创建以下备份：

- **定时备份**：当天有玩家进入过的服务器每天生成一个恢复点，运行中的服务器以不停服方式生成。默认每台服务器保留 7 个，保存 90 天。
- **回收归档**：服务器被放弃、删除或因长期闲置被回收前，先归档世界。

手动操作：

- **立即备份**：已停止的服务器直接归档。运行中的服务器以不停服方式备份，复制世界期间存档暂停数秒，玩家保持在线；不停服备份需要服务器的 RCON 可用。服务器正在启动或停止时，须等其运行或完全停止后再备份。默认每台服务器保留最近 5 个手动备份，保存 30 天，两次手动备份至少间隔 10 分钟，管理员不受间隔限制。
- **恢复此备份**：恢复会停止服务器（有玩家在线时提前 30 秒通知），并用所选备份覆盖当前世界。建议勾选「先为当前世界做安全快照（推荐）」：快照成功后才开始恢复，快照失败则不恢复。需要撤销恢复结果时，恢复「恢复前快照」即可，系统保留最近 3 个恢复前快照。
- **下载备份**：以 `.tar.gz` 格式下载，传输过程按备份时记录的 sha256 校验。
- **导出世界**：须先停止服务器。当前世界打包为 `.tar.gz` 后自动开始下载，下载结束前服务器无法启动，请保持页面打开。
- **删除备份**：备份立即从列表中移除且不再可用于恢复，归档文件在下一次每日清理时删除，异地副本在下一次同步时删除。

回读校验失败的备份标记为「已损坏」，无法完整恢复。「最近操作」列出备份、恢复与导出任务及其失败原因。备份存储达到上限时，服务器所有者的手动备份被拒绝。

::: warning 注意
未勾选安全快照时，恢复会直接覆盖当前世界，没有其他备份的现有数据将无法找回。
:::

保留策略、不停服备份与恢复点的详细说明见[世界备份](/operations/backup#world-backups)、[不停服备份](/operations/backup#live-backups)与[每日恢复点](/operations/backup#restore-points)。备份失败的排查见[备份失败](/operations/troubleshooting#backup-failures)。

## 转发方式 {#forwarding-mode}

转发方式决定游戏代理如何向服务器传递玩家身份。所有者在服务器控制台页的「转发方式」中设置，登录空间与正式大厅不提供此设置。

| 方式 | 适用场景 |
| --- | --- |
| 现代转发 | 默认方式。1.13 及以上版本的服务器使用以代理密钥签名的现代转发。 |
| 传统转发（BungeeCord） | 通过 ViaVersion 接入的旧版本后端。 |

1. 打开服务器控制台页的「转发方式」。
2. 勾选或取消「使用传统转发」，选择「保存」。
3. 完成身份验证。代理在下次刷新服务器列表时生效，约 15 秒内。

::: warning 注意
使用传统转发的服务器信任到达其端口的任何身份。Felis 仅允许代理访问游戏服务器，请勿以其他方式暴露该服务器端口。
:::

此操作由主机节点操作服务执行并记入审计日志。安装时通过 `FELIS_LEGACY_FORWARDING_SERVERS` 指定的服务器（默认 `legacy18`）始终使用传统转发。

## 放弃与删除服务器 {#retire}

服务器所有者可以放弃服务器，管理员还可以删除服务器：

| 操作 | 结果 |
| --- | --- |
| 放弃服务器 | 世界归档后删除世界存储，服务器释放给其他账户认领。 |
| 删除服务器 | 世界归档后删除世界存储与服务器记录，名称与子域名可重新使用。 |

1. 在服务器控制台页的「放弃服务器」卡片中选择「放弃服务器」或「删除服务器」。
2. 输入服务器名称并确认。

提交后服务器进入停止流程，在下一次每日回收时处理；处理完成前服务器保持停止且无法启动。归档默认保留 90 天。处理前可在控制台选择「撤销」取消请求；由管理员提出的删除只能由管理员撤销。放弃的服务器在处理完成前仍计入账户配额。

启用世界回收后，超过 15 天无人游玩的世界会在备份后被删除，见[世界回收](/operations/backup#world-cleanup)。

## 配额 {#quotas}

所有者可为每个账户设置配额，限制其拥有的服务器数量以及 CPU、内存与存储总量；开启[自助建服](/guide/administration#self-service)后，未单独设置配额的账户使用默认配额。配额在以下情况下检查：

- 自助创建服务器时，按所选规格计算。
- 认领服务器时，按该服务器的实际规格计算。
- 增加已归属服务器的 CPU 或内存时。
- 通过账户迁移接收服务器时。

超出配额的操作被拒绝。降低配额只限制后续操作，不影响已有服务器。配额的设置方法见[配额](/guide/administration#quotas)。
